# AEO for virtara.co.za: findings and build spec

Written 15 November 2026. Source of practice: `AEO research notes 2026.md` (owner's document). Its main rules: AEO is still SEO; the answer must be in the HTML crawlers receive; lead with the answer; headings should match real questions; schema must match visible text; llms.txt is optional and gives no lift; do not mass-produce thin pages.

## 1. What the site check found (live, 15 Nov)

| Check | Result |
|---|---|
| Search bots (Googlebot, Bingbot, OAI-SearchBot, PerplexityBot, Claude-SearchBot) | All get 200 and full HTML. robots.txt allows all. Pass. |
| Structured data (JSON-LD) | **None in any page's HTML.** Home defines one in Helmet but the prerender drops `<script>` tags. |
| Blog posts | **Not in the HTML and not in the sitemap.** 5 posts load in the browser only, so crawlers see an empty page. |
| Unknown URLs | **Return 200** with the home page (soft 404). `/llms.txt` does this too. |
| `<title>` | Two per page (the static one from `index.html`, then the page's). Same for description and Open Graph tags, which always describe the home page. |
| Titles and descriptions | Written in brand words ("digital assets", "conversion-focused"), not the words people search. |
| Question-and-answer content | None outside the blog. |
| IndexNow / Bing | Not set up. |

## 3. Build spec

Scope is closed. Work on `develop`, no worktrees, no push. Invoke `karpathy-guidelines` before code and `impeccable` + `ui-ux-pro-max` before any visible change. Nothing may touch `window`/`document` during render. One commit per agent, pathspec form, message ending `Co-Authored-By: Claude <noreply@anthropic.com>`. Never `git add -A`; leave `.gitignore` files alone. Gate: `npm run lint` and `npm run build` exit 0.

No invented facts. Every price comes from `src/data/pricing.js`. No rankings promised, no statistics, no client claims, no competitor names.

### Agent A: technical (owns `scripts/`, `src/entry-server.jsx`, `src/main.jsx`, `vite.config.js`, `vercel.json`, `index.html`, `package.json`, `public/`, `src/App.jsx`, `src/lib/sanity.js`, `src/pages/Blog.jsx`, `src/pages/BlogPost.jsx`, new `src/components/seo/SiteSchema.jsx`, new `src/pages/NotFound.jsx`)

A1. **Emit Helmet scripts.** In `entry-server.jsx` add `helmet.script` to the head string. Agent B relies on this.

A2. **One title and description per page.** In `prerender.mjs`, when the page's Helmet output has a `<title>`, remove the template's static `<title>`; same for `meta name="description"`. Then set the template's `og:title`, `og:description`, `og:url`, `twitter:title`, `twitter:description` to the page's title, description and canonical URL (string replace on the template is fine). Verify: each built page has exactly one `<title>` and one description, and `og:url` equals the canonical.

A3. **Site-wide schema.** `SiteSchema.jsx`, rendered once in `App.jsx`, outputs via Helmet one JSON-LD `@graph` with:
- `Organization` + `ProfessionalService` (one node, `@id` `https://virtara.co.za/#organization`): name `Virtara`, url, logo `https://virtara.co.za/web_logo_bg.svg`, email `info@virtara.co.za`, telephone `+27723271040`, address (16 Hume Road, Johannesburg, 2092, ZA), `areaServed` South Africa, `sameAs` the three social URLs in `Footer.jsx`, `priceRange` `R4,900 – R55,000` built from `pricing.js`.
- `WebSite` (`@id` `…/#website`, publisher → the organisation).
Remove the old inline `ProfessionalService` script from `Home.jsx` (this one line in Home is yours; B knows).

A4. **Blog posts in the HTML and the sitemap.**
- At build, `prerender.mjs` fetches all posts from Sanity (project `h9swrh5t`, dataset `production`, public, no token) with the same fields `Blog.jsx` and `BlogPost.jsx` query, and prerenders `/web-development-blog` and each `/web-development-blog/<slug>` with the content in the HTML.
- Pass the data through `render(url, data)` into a small React context; `Blog` and `BlogPost` use it as initial state and skip the loading state when it is present. Embed the same data for that page in the HTML as a JSON script (escape `<`) and have `main.jsx` read it so hydration matches. Slugs that were not prerendered must still load in the browser exactly as today.
- `BlogPost` Helmet: canonical, description (excerpt or first 155 characters of body), and `BlogPosting` JSON-LD (headline, description, image if any, `datePublished`, `dateModified` from `_updatedAt`, author and publisher → `#organization`, `mainEntityOfPage`). Show the published date and "Updated" date in visible text if not already shown.
- Add every post URL to the sitemap with its real `lastmod`. Static pages keep the build date. If `vite-plugin-sitemap` cannot take per-URL dates, write the sitemap in `prerender.mjs` and drop the plugin.
- If Sanity is unreachable at build, log a warning and build without post pages; do not fail the deploy.

A5. **Real 404s.**
- `NotFound.jsx`: `PageShell`-style page, heading "Page not found", one line, buttons to `/` and `/services`, Helmet `noindex`. Route `path="*"` in `App.jsx`.
- Prerender it to `dist/404.html` (not in the sitemap).
- `vercel.json`: replace the catch-all rewrite with explicit rewrites to `/index.html` for only the client-rendered routes in `App.jsx` that are not prerendered (`/contact`, `/starta-project`, `/checklist`, `/thank-you`, `/audit`, `/unsubscribe`, `/comeback`, every `…/thank-you` path, `/web-development-blog/:slug`). List them from `App.jsx`; do not guess.
- Verify with `npx vercel build` + a static check if possible; otherwise say plainly it is unverified. The coordinator checks live after deploy.

A6. **IndexNow.** Generate a key (32 hex), save `public/<key>.txt` containing the key. `scripts/indexnow.mjs`: POST all sitemap URLs to `https://api.indexnow.org/indexnow` (host `virtara.co.za`, `keyLocation`), only when `process.env.VERCEL_ENV === 'production'`; never fail the build on error. Append it to the `build` script.

A7. **robots.txt:** keep as is, and add a comment block naming the search crawlers it allows (Googlebot, Bingbot, OAI-SearchBot, PerplexityBot, Claude-SearchBot). No training-bot rules: that is an owner decision. No `llms.txt`.

**/seo** (heading: "SEO and AEO questions")
1. *What is AEO?* Answer engine optimisation (AEO) is the work of getting your business named and linked when someone asks ChatGPT, Gemini, Perplexity or Google's AI Overviews a question. It builds on SEO: the page must be crawlable, answer the question plainly and be backed by trusted mentions elsewhere.
2. *What is the difference between SEO and AEO?* SEO gets a page ranked in search results. AEO gets the business cited inside a generated answer. The foundations are the same, and Google says its AI features draw on the same search index, so we do both together.
3. *Does SEO still work?* Yes. Google's AI Overviews and AI Mode are built on Google Search, so a page that is indexed, helpful and trusted is still what gets shown and cited.
4. *Can I do SEO myself?* You can do the basics yourself: a complete Google Business Profile, clear page titles, and pages that answer what customers ask. An agency helps when you need technical fixes, steady content and reporting.
5. *How do I get my business to show up in ChatGPT?* Let its search crawler read your site, put clear answers in plain text on your pages, and earn genuine mentions on sites it already trusts, such as reviews and directories. Nobody can guarantee a mention.
6. *How much does SEO cost?* From {seo[0].priceLabel} with no setup fee. A once-off {aeoStarter.name} is {aeoStarter.price}.

2. *How does an AI chatbot learn about my business?* Concierge reads your website and drafts what it knows: services, prices, areas and hours. You check it before it goes live.
3. *Can AI chatbots make mistakes?* Yes, any AI can. Concierge answers from the information you approved, and tells visitors to check anything important with you.
